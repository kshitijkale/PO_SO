# Methodology Artifact: FLEX (Forward Learning from Experience)

## 1. Core Concept

FLEX replaces parameter learning with experience learning.

Instead of modifying model weights, the system:

- explores problems
- extracts reasoning experiences
- stores them in an evolving experience library
- retrieves relevant experiences during future reasoning

Thus the system improves through forward interaction with accumulated experience rather than gradient updates.

## 2. System Architecture

FLEX contains four primary components.

### 2.1 Actor Agent (`π`)

The actor is a frozen LLM responsible for:

- generating reasoning trajectories
- exploring solution paths
- producing candidate answers

The actor does not change its parameters.

### 2.2 Critic Agent

The critic evaluates actor outputs and produces semantic feedback.

The critic:

- identifies errors
- explains why reasoning failed
- extracts generalized lessons
- converts them into structured experiences

This feedback acts as a semantic analogue of gradients.

### 2.3 Updater Agent (`µ`)

The updater maintains and evolves the Experience Library (`E`).

Responsibilities:

- deduplicate experiences
- merge similar entries
- place experiences into the correct hierarchy
- maintain knowledge quality

### 2.4 Experience Library (`E`)

The experience library is a structured memory of distilled reasoning knowledge.

The library stores:

- strategies
- reasoning templates
- problem-solving patterns
- failure modes
- warnings
- examples

The library continuously evolves as more experiences are collected.

## 3. Two-Level Learning Structure

FLEX learning operates through two nested decision processes.

### 3.1 Base-Level Process (Experience Exploration)

Purpose:

- Generate experiences from solving individual problems.

This is implemented as an Actor-Critic loop.

State:

- current reasoning context and accumulated experiences

Action:

- a full reasoning trajectory generated by the actor

Reward:

- semantic evaluation from the critic

Transition:

- refined reasoning based on critic feedback

### 3.2 Meta-Level Process (Library Evolution)

Purpose:

- improve the experience library itself

State:

- current experience library

Action:

- integrate newly discovered experiences

Transition:

- library update

Reward:

- improvement in solution correctness across tasks

## 4. The FLEX Learning Loop

The full FLEX system runs the following continuous cycle.

### Phase 1 - Forward Exploration

Input: problem `X`

The actor generates multiple candidate reasoning trajectories.

Two scaling strategies are used.

#### Parallel Exploration

Generate many reasoning attempts simultaneously.

Implementation:

```python
for i in 1..N:
    trajectory_i = actor.solve(problem)
```

Example methods:

- rejection sampling
- diverse decoding
- temperature variation

Goal:

- Explore multiple reasoning hypotheses.

#### Sequential Refinement

Each trajectory is iteratively improved.

Loop:

```python
for iteration t:

    candidate_solution = actor(reasoning_trace, feedback)

    evaluation = critic(candidate_solution)

    feedback = critic.generate_improvement()

    reasoning_trace = reasoning_trace + feedback
```

The loop stops when:

- the solution becomes correct
- improvement stalls
- iteration limit is reached

### Phase 2 - Experience Distillation

After exploration, reasoning traces are converted into experiences.

The critic extracts knowledge such as:

#### From successful trajectories

- strategies that worked
- key insights
- reasoning templates

Example:

```text
Golden Rule:
If a combinatorics problem involves cyclic symmetry,
apply Burnside's lemma rather than direct enumeration.
```

#### From failed trajectories

- failure patterns
- incorrect assumptions
- warnings

Example:

```text
Warning:
Direct symbolic expansion causes exponential complexity.
Use factorization identities instead.
```

### Phase 3 - Experience Library Update

The updater integrates new experiences into the library.

#### Deduplication

If an identical entry exists:

- discard experience

#### Merge

If semantically similar entries exist:

- merge entries
- retain highest-quality formulation
- remove redundancy

#### Insert

Otherwise:

- add new entry
- place in correct hierarchy
- assign to golden or warning zone

## 5. Experience Library Structure

The library has two orthogonal structures.

### 5.1 Dual Zones

#### Golden Zone

Stores successful strategies.

Contains:

- problem-solving principles
- reasoning rules
- best practices

#### Warning Zone

Stores failures and pitfalls.

Contains:

- common mistakes
- misleading reasoning patterns
- invalid heuristics

### 5.2 Hierarchical Knowledge Levels

Experiences are organized into three levels.

#### Level 1 - Strategic Principles

High-level guidance.

Example:

```text
For optimization problems:
Transform search into convex formulation when possible.
```

#### Level 2 - Reasoning Patterns

Reusable procedures.

Example:

```text
To prove divisibility:

1. express expression modulo n
2. simplify algebraically
3. evaluate remainder
```

#### Level 3 - Concrete Examples

Specific instances.

Example:

```text
Example:
AIME 2025 problem #6 solved using modular invariance.
```

## 6. Experience Retrieval During Reasoning

When solving a new task, the agent queries the library.

Input:

- query `q`
- experience library `E`

The retrieval process is context-aware.

### Step 1 - Strategy Retrieval

Identify relevant high-level principles.

Example output:

```text
Strategy:
Use invariant-based reasoning.
```

### Step 2 - Pattern Retrieval

Find reasoning templates related to the strategy.

Example:

```text
Pattern:
For invariants in iterative systems:

1. identify quantity preserved under operation
2. test with small examples
3. prove formally
```

### Step 3 - Example Retrieval

Retrieve concrete cases.

Example:

```text
Example:
Similar invariant problem solved via parity conservation.
```

The agent then solves the problem using:

```text
LLM(query + retrieved_experiences)
```

## 7. Dynamic Retrieval During Reasoning

Retrieval is not limited to the beginning.

The agent can query the library at any point.

Example loop:

```python
while reasoning:

    if uncertainty detected:
        retrieve additional experiences

    integrate retrieved knowledge

    continue reasoning
```

## 8. Experience Scaling

The paper observes that performance scales with library size.

As more experiences accumulate:

- reasoning improves
- uncertainty decreases
- solutions become more reliable

The library becomes a knowledge substrate for reasoning.

## 9. Experience Inheritance Across Agents

The experience library is model-independent.

Therefore it can be transferred.

Example:

```text
Agent A learns experiences.

Export experience library.

Agent B imports library.

Agent B immediately gains learned strategies.
```

This enables plug-and-play knowledge transfer.

## 10. Full FLEX Algorithm

```python
initialize experience_library E

for each training problem (X, Y):

    trajectories = parallel_explore(actor, X)

    for trajectory in trajectories:

        refined_trajectory = sequential_refine(actor, critic)

        experience = critic.distill(refined_trajectory)

        E = updater.integrate(E, experience)

return E
```

## 11. Inference Algorithm

```python
function solve(query q):

    strategies = retrieve_strategies(E, q)

    patterns = retrieve_patterns(E, q)

    examples = retrieve_examples(E, q)

    response = actor(q + strategies + patterns + examples)

    return response
```

## 12. Key Properties of FLEX

- No gradient updates. Learning occurs via experience accumulation.
- Continual learning. The library grows indefinitely.
- Interpretability. Experiences are stored as human-readable knowledge.
- Transferability. Libraries can be shared across agents.
- Scalability. Performance improves with more experiences.

## 13. Conceptual Flow

The full lifecycle:

```text
Problem -> Exploration -> Reflection -> Experience Extraction
-> Library Update -> Library Growth -> Experience Retrieval
-> Improved Reasoning
```
